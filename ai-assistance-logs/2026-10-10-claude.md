QDVC Progress is to be a Mac app built with Swift that helps the user keep track of their projects and progress on those projects.

   * No work was done; OR: work was done, of size XS or S or M or L or XL.    * Special labels exist: mtg (for a meeting taking place that day), (!) (for a due date), (P) (for work planned to be undertaken, typically used for planning future days ahead). A project can also be marked as inactive for a day (typically used for a number of days, e.g., when a project is on hold for a few weeks). A label can be displayed for a period of project inactivity.

* `mtg` should also be mapped to a workload size, default "M" (3 under the default preset)
* At the bottom of the grid, the sum of the total work done per day, mapped based on the size mappings above, is displayed for each day, as well as for the working week and weekend.
* It is also possible to mark an entire project as inactive (this is not related to periods of inactivity, it is a project-level flag attribute).

### How it's laid out

I agree with you on navigation: one window with no tab bar or sidebar. A sidebar would take width from the days, which is what you most want to see. You get:

- **The grid.** The header, project columns and totals stay frozen while the days scroll. The range grows automatically as you scroll back or forward.
- **An inspector on the right (⌥⌘I).** It has two tabs:
  - **Day:** label buttons, the note, the inactive period and its label, and the Copy & Paste setting (label and note, label only, or note only).
  - **Project:** title, ID, programme, target, collaborators, the active flag, inactive periods and recent workload.
- **Filtering and sorting in the toolbar:** a programme pop-up, a status filter, a sort menu and a search field. Programme headings fold, and clicking a column heading sorts by it.
- **Fast typing in the grid:**
  - 1–5 sets XS–XL; m, !, p set mtg, (!), (P); 0 or Delete clears.
  - i marks days inactive; Return edits the note.
  - Copy, cut and paste work with ⌘C, ⌘X, ⌘V. A single copied cell fills the whole selection.
- **Week labels (⌥⌘L).** Paste two columns from a spreadsheet: a date in the week and its label. A live preview shows how each row is read. It understands most date formats, including Excel serial numbers. Double-click a week in the header to label just that week.
- **Totals.** The bottom rows show a daily total plus Mon–Fri and weekend totals in salmon-to-red. They follow the filter, with a toggle for all projects.

### Workspace files

- `progress.yml` holds the size mapping and colour peak.
- `projects.yml` holds programmes and projects. Each project has a stable key, so you can rename it freely, and its inactive periods with their labels.
- `log/2026/2026-10.csv` holds the log, one row per project per day. Months are separate files, so commits stay small.
- `week-labels.csv` holds the week labels.

`docs/FILE_FORMAT.md` documents all of these. `sample-workspace/` has realistic data up to today.

### Size presets

Linear (1–5) is still the default. I added Fibonacci (1, 2, 3, 5, 8), which I'd recommend, and Doubling (1, 2, 4, 8, 16). Under Linear, a week with two XL days totals 10, less than five M days (15). That understates how draining big days are; Fibonacci makes it 16 vs 15.

```
# Build with full Xcode's toolchain. From Xcode 27, SwiftUI's @State is a
# macro, and its implementation (the SwiftUIMacros compiler plugin) comes
# with Xcode: a build with the Command Line Tools alone, or with a swift.org
# toolchain, fails with "plugin for module 'SwiftUIMacros' not found".
# The newest Xcode installed (by major version), or nothing.
newest_xcode() {
    local best="" best_major=0 x v major
    while IFS= read -r x; do
        [[ -d "$x" ]] || continue
        v="$(defaults read "$x/Contents/Info" CFBundleShortVersionString 2>/dev/null || echo 0)"
        major="${v%%.*}"
        [[ "$major" =~ ^[0-9]+$ ]] || continue
        if (( major > best_major )); then best="$x"; best_major=$major; fi
    done < <({ mdfind "kMDItemCFBundleIdentifier == 'com.apple.dt.Xcode'" 2>/dev/null || true
               ls -d /Applications/Xcode*.app 2>/dev/null || true; } | sort -u)
    echo "$best"
}

if [[ -z "${DEVELOPER_DIR:-}" ]] && [[ "$(xcode-select -p 2>/dev/null || true)" == *CommandLineTools* ]]; then
    xcode="$(newest_xcode)"
    if [[ -n "$xcode" ]]; then
        export DEVELOPER_DIR="$xcode/Contents/Developer"
        echo "==> Using $xcode (xcode-select points at the Command Line Tools)"
    else
        echo "warning: building with the Command Line Tools; if it fails with \"SwiftUIMacros\" not found, install Xcode" >&2
    fi
fi
# xcrun: Xcode's swift, even if another toolchain comes first on PATH.
echo "==> $(xcrun swift --version 2>&1 | head -n 1)"
sdk="$(xcrun --sdk macosx --show-sdk-version 2>/dev/null || echo unknown)"
echo "==> macOS SDK $sdk ($(xcode-select -p 2>/dev/null || true)${DEVELOPER_DIR:+, DEVELOPER_DIR=$DEVELOPER_DIR})"
sdk_major="${sdk%%.*}"
if [[ "$sdk_major" =~ ^[0-9]+$ ]] && (( sdk_major < 26 )); then
    newer="$(newest_xcode)"
    echo "warning: the macOS $sdk SDK predates Liquid Glass, so the app will have the classic look." >&2
    echo "         Build with Xcode 26 or later for Liquid Glass${newer:+ (newest installed: $newer)}." >&2
fi
```
